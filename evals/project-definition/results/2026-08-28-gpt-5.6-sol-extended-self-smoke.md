## Case 007 — Authoritative destination failure

### Runtime evidence

A deliberately stale content revision was used for a write to the selected repository destination. The connected write returned HTTP `409` and no content was changed.

The failure path did not claim success, did not create a fallback canonical copy, and did not change the authoritative destination. The correct recovery choices are retry after re-reading destination state, save a clearly non-authoritative copy if requested, or explicitly select a new canonical destination.

### Rubric

All 10 dimensions: **2/2**.

**Total:** 20/20
