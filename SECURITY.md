# Security Policy

## Reporting a vulnerability

Please do not disclose suspected security vulnerabilities in a public issue.

Use a private repository security-reporting channel when one is available. If no private reporting channel is configured, contact the repository maintainer privately through an appropriate account-level contact method.

Include, where possible:

- the affected skill, script, or workflow;
- a clear description of the issue;
- reproduction steps;
- potential impact;
- any suggested mitigation.

## Security scope

Security reports may include, but are not limited to:

- instructions that could expose credentials or confidential information;
- unsafe handling of external tools or local files;
- unintended cross-project data leakage;
- scripts with insecure execution behavior;
- prompt or workflow behavior that bypasses explicit human approval boundaries.

Never include real credentials, access tokens, private client data, or other secrets in a report.
